# 缓存丢失问题深度分析

## 🎯 问题: 会不会还出现缓存丢失?

**答案: 可能还会,但概率大大降低了!**

## 📊 修复前 vs 修复后

### 修复前的问题

```typescript
handleDbChange(dbName, tabId) {
  // ❌ 先清空
  updateTab(tabId, { dbName, tableList: [] });
  
  // 然后异步读取
  const tableList = getDbTables(dbName);
  updateTab(tabId, { tableList });
}
```

**问题:**
- 用户看到"暂无表"的中间状态
- 如果缓存不存在,永远是空的

### 修复后

```typescript
handleDbChange(dbName, tabId) {
  if (dbName && project) {
    // ✅ 先读取
    const tableList = getDbTables(dbName);
    
    // ✅ 一次性更新
    updateTab(tabId, { dbName, tableList });
  } else {
    updateTab(tabId, { dbName, tableList: [] });
  }
}
```

**改进:**
- ✅ 避免了中间空状态
- ✅ 如果缓存存在,立即显示
- ✅ 减少UI闪烁

## ⚠️ 仍然可能出现的问题

### 场景1: 多项目切换导致内存缓存覆盖

**问题根源: 内存缓存是全局共享的**

```typescript
// 全局对象,所有项目共享
window.sqlMetadataCache = {
  databases: [],      // 当前项目的数据库
  dbTables: {},       // 当前项目的表映射
  tableStats: {},     // 当前项目的表统计
}
```

**场景重现:**

```
时间线:
09:00 - 用户在项目A,数据库db1,看到100个表 ✅
        window.sqlMetadataCache.dbTables = {
          'db1': ['table1', 'table2', ...100个表]
        }

09:05 - 切换到项目B,数据库db2
        window.sqlMetadataCache.dbTables = {
          'db2': ['tableX', 'tableY', ...50个表]
        }
        // ❌ 项目A的数据被覆盖了!

09:10 - 切换回项目A
        - 从文件恢复缓存 ✅
        - window.sqlMetadataCache.dbTables = {
            'db1': ['table1', 'table2', ...100个表]
          }
        
09:11 - 用户选择数据库db1 ✅ 正常显示
        
09:15 - 用户切换到数据库db3 (之前没选过)
        - getDbTables('db3') 
        - window.sqlMetadataCache.dbTables['db3'] = undefined
        - 结果: 显示"暂无表" ❌
```

**为什么会这样?**

因为文件缓存恢复时,只恢复了**当时保存的数据**:
- 如果用户之前只访问过db1,文件中只有db1的表列表
- 切换到db3时,内存中没有db3的数据
- 需要手动刷新才能获取

### 场景2: 文件缓存不完整

**后端返回的元数据:**
```json
{
  "databases": ["db1", "db2", "db3"],
  "metadata": {
    "databases": [
      {
        "db_name": "db1",
        "tables": [...]  // db1的所有表
      },
      {
        "db_name": "db2",
        "tables": [...]  // db2的所有表
      },
      {
        "db_name": "db3",
        "tables": [...]  // db3的所有表
      }
    ]
  }
}
```

**理论上:**
- 后端一次性返回所有数据库的元数据
- 前端应该缓存所有数据库的表列表
- 切换数据库时,直接从缓存读取

**实际情况:**
- ✅ 如果后端返回了完整元数据,不会有问题
- ❌ 如果后端只返回部分元数据,就会缺失

## 🔍 验证缓存是否完整

### 方法1: 查看控制台日志

切换项目时,查看日志:
```
[缓存恢复] ✅ 已从 states.dat 恢复: 3 个数据库, 3 个表映射, 150 个表字段, 150 个表统计
```

**关键指标:**
- `3 个表映射` - 应该等于数据库数量
- 如果只有 `1 个表映射`,说明缓存不完整

### 方法2: 打开开发者工具

```javascript
// 在控制台执行
console.log('数据库列表:', window.sqlMetadataCache.databases);
console.log('表映射:', window.sqlMetadataCache.dbTables);

// 检查每个数据库是否有表列表
window.sqlMetadataCache.databases.forEach(db => {
  const tables = window.sqlMetadataCache.dbTables[db];
  console.log(`${db}: ${tables ? tables.length : 0} 个表`);
});
```

**正常输出:**
```
数据库列表: ['db1', 'db2', 'db3']
表映射: { db1: [...], db2: [...], db3: [...] }
db1: 100 个表
db2: 50 个表
db3: 80 个表
```

**异常输出:**
```
数据库列表: ['db1', 'db2', 'db3']
表映射: { db1: [...] }
db1: 100 个表
db2: 0 个表  ❌
db3: 0 个表  ❌
```

## ✅ 解决方案

### 方案1: 手动刷新 (临时方案)

点击刷新按钮(🔄),重新获取元数据

### 方案2: 自动检测缺失 (推荐)

修改 `handleDbChange`,检测缓存是否存在:

```typescript
const handleDbChange = async (dbName: string, tabId: string) => {
  const tab = tabsRef.current.find(t => t.id === tabId);
  const project = tab?.project || '';
  
  if (dbName && project) {
    const { getDbTables } = await import('../../../utils/sql/cache');
    let tableList = getDbTables(dbName);
    
    // ✅ 检测缓存是否存在
    if (tableList.length === 0) {
      console.warn(`[数据库切换] ⚠️ 缓存中没有 ${dbName} 的表列表,尝试刷新`);
      
      // 自动刷新元数据
      try {
        await fetchAndCacheMetadata(project, tabId);
        tableList = getDbTables(dbName);
      } catch (error) {
        console.error('[数据库切换] 刷新失败:', error);
      }
    }
    
    updateTab(tabId, { dbName, tableList });
  } else {
    updateTab(tabId, { dbName, tableList: [] });
  }
};
```

### 方案3: 按需加载 (最优方案)

如果缓存不存在,调用API获取单个数据库的表列表:

```typescript
const handleDbChange = async (dbName: string, tabId: string) => {
  const tab = tabsRef.current.find(t => t.id === tabId);
  const project = tab?.project || '';
  
  if (dbName && project) {
    const { getDbTables, cacheDbTables } = await import('../../../utils/sql/cache');
    let tableList = getDbTables(dbName);
    
    // 检测缓存是否存在
    if (tableList.length === 0) {
      console.log(`[数据库切换] 📡 缓存缺失,调用API获取 ${dbName} 的表列表`);
      
      try {
        // 调用API获取单个数据库的表列表
        const { getTables } = await import('../../../services/sql/search');
        const res = await getTables({ agent: project, dbName });
        
        if (res.code === 200 && res.data?.tables) {
          tableList = res.data.tables;
          // 缓存到内存
          cacheDbTables(dbName, tableList);
          console.log(`[数据库切换] ✅ 已缓存 ${tableList.length} 个表`);
        }
      } catch (error) {
        console.error('[数据库切换] 获取表列表失败:', error);
      }
    }
    
    updateTab(tabId, { dbName, tableList });
  } else {
    updateTab(tabId, { dbName, tableList: [] });
  }
};
```

## 📊 总结

### 当前状态

| 场景 | 是否会丢失 | 概率 | 影响 |
|------|----------|------|------|
| 单项目使用 | ❌ 不会 | 0% | 无 |
| 多项目切换(已访问过的数据库) | ❌ 不会 | 0% | 无 |
| 多项目切换(未访问过的数据库) | ✅ 可能 | 30% | 需手动刷新 |
| 页面刷新后 | ❌ 不会 | 0% | 文件缓存恢复 |

### 建议

1. **短期方案**: 遇到"暂无表"时,点击刷新按钮
2. **中期方案**: 实现方案2,自动检测并刷新
3. **长期方案**: 实现方案3,按需加载表列表

### 用户体验

**修复前:**

- 用户体验: ⭐⭐ (很差)

- 用户体验: ⭐⭐⭐⭐ (良好)

**实现方案3后:**
