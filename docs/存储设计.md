# 本地存储架构设计

## 概述

所有本地数据统一使用 Tauri Store 插件存储，通过 Rust 端设备密钥加密。按数据类型分类存储，用户数据以用户名为 key 存储在同一文件中。

**存储架构：**
- `app.dat` - 公共配置（登录历史、默认主题、更新信息）
- `tokens.dat` - 单用户 token
- `profiles.dat` - 用户数据（用户信息、权限、菜单）
- `states/` - 使用状态（分片存储，提升大文件性能）
- `preferences.dat` - 偏好设置（主题、窗口、头像）
- `credentials.dat` - 设备凭据（Rust 端管理）

## 存储文件结构

```
%APPDATA%/com.cmdb.desktop/
├── app.dat                 # 1. 公共存储（登录历史、默认主题等）
├── tokens.dat              # 2. Token 存储（单用户 token）
├── profiles.dat            # 3. 用户数据（用户信息、权限、菜单）
├── states/                 # 4. 使用状态（分片存储）
│   ├── index.dat           #    索引文件（迁移状态、分片版本）
│   ├── navigation.dat      #    导航状态（标签页、路由、侧边栏）
│   ├── page-states.dat     #    页面快照（表单、滚动位置）
│   ├── sqlSearch/          #    SQL 查询页状态（按 Tab 分片）
│   │   ├── index.dat       #      用户-Tab 索引
│   │   └── <tabId>.dat     #      单个 Tab 状态
│   └── sqlMetadata/        #    SQL 元数据缓存
│       ├── index.dat       #      元数据索引（项目列表）
│       └── <项目名>.dat    #      各项目元数据
├── preferences.dat         # 5. 偏好设置（主题、窗口、头像）
└── credentials.dat         # 6. 设备凭据（Rust 端管理，自动登录凭证）
```

**说明：** 原 `states.dat` 已拆分为多个分片文件，提升大文件读写性能。首次启动时自动迁移旧数据。

## 各文件数据结构

### 1. `app.dat` - 公共存储

```json
{
  "loginHistory": ["admin", "test", "user1"],
  "lastUser": "admin",
  "defaultTheme": "dark",
  "appVersion": "1.0.0",
  "installPath": "C:/Users/.../AppData/Local/cmdb-desktop",
  "lastUpdateCheck": 1704067200000,
  "update": {
    "latestVersion": "1.1.0",
    "downloadedVersion": "1.1.0",
    "downloadedPath": "C:/Users/.../cmdb-desktop-1.1.0.msi",
    "downloadStatus": "completed",
    "downloadProgress": 100,
    "changelog": "1. 新增功能A\n2. 修复问题B",
    "lastCheckTime": 1704067200000
  }
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| loginHistory | string[] | 登录过的用户名（最多10个，由 Rust 端管理） |
| lastUser | string | 最后登录的用户名 |
| defaultTheme | 'light' \| 'dark' | 未登录时的默认主题 |
| appVersion | string | 当前应用版本号 |
| installPath | string | 应用安装路径（用于更新安装包定位） |
| lastUpdateCheck | number | 最后检查更新时间 |
| update | object | 更新信息（见下表） |

**update 字段说明：**

| 字段 | 类型 | 说明 |
|-----|------|------|
| latestVersion | string | 服务器最新版本号 |
| downloadedVersion | string | 已下载的版本号 |
| downloadedPath | string | 已下载文件的本地路径 |
| downloadStatus | string | 下载状态：none / downloading / completed / failed |
| downloadProgress | number | 下载进度 0-100 |
| changelog | string | 更新日志 |
| lastCheckTime | number | 最后检查时间戳 |

**写入时机：** 登录成功、退出登录、检查更新、下载更新
**清除时机：** 不参与「清除缓存」逻辑，永久保留

---

### 2. `tokens.dat` - Token 存储

```json
{
  "token": "eyJhbGc...",
  "username": "admin",
  "expireAt": 1704153600000
}
```

单用户 token 存储，每次只保存一个用户的 token。

| 字段 | 类型 | 说明 |
|-----|------|------|
| token | string | JWT token |
| username | string | token 对应的用户名 |
| expireAt | number | 过期时间戳 |

**写入时机：** 登录成功且用户勾选"保存登录状态"
**清除时机：** 退出登录、token 过期
**特殊说明：** 
- 登录页提供"保存登录状态"开关
- 勾选：token 加密写入文件，下次启动自动登录
- 不勾选：token 仅存内存，关闭软件后失效（支持多开场景）

---

### 3. `profiles.dat` - 用户数据

```json
{
  "admin": {
    "userInfo": { "id": "1", "nick_name": "管理员", "email": "admin@test.com" },
    "permissions": ["system:user:r", "system:role:rw"],
    "menus": [...],
    "roleId": 1,
    "roleName": "超级管理员"
  },
  "test": {
    "userInfo": {...},
    "permissions": [...],
    "menus": [...],
    "roleId": 2,
    "roleName": "普通用户"
  }
}
```

以用户名为 key，存储用户核心业务数据。

| 字段 | 类型 | 说明 |
|-----|------|------|
| userInfo | UserInfo | 用户基本信息（id、nick_name、email、phone、role等） |
| permissions | string[] | 权限码列表（:rw 会自动拆分为 :r 和 :w） |
| menus | MenuItem[] | 菜单快照（当前主要从接口实时获取） |
| roleId | number | 角色 ID |
| roleName | string | 角色名称 |

**写入时机：** 登录成功、刷新权限、获取用户信息
**清除时机：** 退出登录（可选）、**点击「清除缓存」按钮时物理删除整个文件**

---

### 4. `states/` - 使用状态（分片存储）

原 `states.dat` 已拆分为多个分片文件，提升大文件读写性能。

**迁移来源：** 所有分片数据均来源于旧的 `states.dat`，首次启动时自动迁移。
**清除方式：** 清除缓存时直接删除整个 `states/` 目录。

#### 4.1 `states/index.dat` - 索引文件

```json
{
  "schemaVersion": 1,
  "migrationCompleted": true,
  "legacySource": "states.dat",
  "files": {
    "navigation": { "file": "states/navigation.dat", "version": 1, "updatedAt": 1704067200000 },
    "pageStates": { "file": "states/page-states.dat", "version": 1, "updatedAt": 1704067200000 }
  },
  "updatedAt": 1704067200000
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| schemaVersion | number | 分片架构版本号（当前为 1） |
| migrationCompleted | boolean | 是否已完成从 states.dat 的迁移 |
| legacySource | string | 迁移来源（固定为 "states.dat"） |
| files | Record<string, StateIndexEntry> | 各分片文件信息 |
| updatedAt | number | 最后更新时间戳 |

#### 4.2 `states/navigation.dat` - 导航状态

```json
{
  "admin": {
    "visitedViews": [{ "path": "/dashboard", "name": "Dashboard", "title": "首页" }],
    "cachedViews": ["Dashboard"],
    "activeRoute": "/dashboard",
    "sidebarCollapsed": false,
    "lastSnapshot": 1704067200000
  }
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| visitedViews | ViewItem[] | 已打开的标签页列表 |
| cachedViews | string[] | 需要 keep-alive 缓存的页面名 |
| activeRoute | string | 当前激活路由 |
| sidebarCollapsed | boolean | 侧边栏折叠状态 |
| lastSnapshot | number | 最后快照时间戳 |

#### 4.3 `states/page-states.dat` - 页面快照

```json
{
  "admin": {
    "pageStates": {
      "audit/search": {
        "formData": { "keyword": "login", "dateRange": ["2025-01-01", "2025-06-15"] },
        "scrollTop": 120
      },
      "monitor/overview": {
        "timeRange": "1h",
        "refreshInterval": 30
      }
    },
    "lastSnapshot": 1704067200000
  }
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| pageStates | Record<string, PageState> | 页面快照（表单、滚动位置等） |
| lastSnapshot | number | 最后快照时间戳 |

**注意：** SQL 查询页（`sql/search`、`sql/detached-tabs`）的状态不存储在此文件，而是存储在 `states/sqlSearch/` 目录（按 Tab 分片）。

#### 4.4 `states/sqlSearch/` - SQL 查询页状态（按 Tab 分片）

```
states/sqlSearch/
├── index.dat           # 用户-Tab索引（记录每个用户关联的 tabId 列表）
└── <tabId>.dat         # 单个 SQL Tab 的状态
```

**设计目的：** 用户经常创建多个 Tab，但实际操作只操作一个 Tab。按 Tab 分片后，自动保存只写入当前操作的 Tab 文件，避免全量保存所有 Tab，减少卡顿。

**index.dat 结构：**
```json
{
  "schemaVersion": 1,
  "source": "states.dat",
  "migration": {
    "source": "states.dat",
    "status": "completed",
    "startedAt": 1704067200000,
    "completedAt": 1704067300000
  },
  "users": {
    "admin": {
      "userName": "admin",
      "tabIds": ["uuid-1", "uuid-2", "uuid-3"],
      "activeTabId": "uuid-2",
      "detachedTabIds": ["uuid-3"],
      "updatedAt": 1704067200000
    }
  },
  "updatedAt": 1704067200000
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| migration | object | 迁移状态（从 states.dat 迁移） |
| users | Record<string, SqlSearchUserIndex> | 各用户的 Tab 索引 |
| users[username].tabIds | string[] | 用户所有 Tab ID 列表 |
| users[username].activeTabId | string | 当前激活的 Tab ID |
| users[username].detachedTabIds | string[] | 分离窗口的 Tab ID 列表 |

**单个 Tab 文件结构（如 uuid-2.dat）：**
```json
{
  "tabId": "uuid-2",
  "name": "查询 1",
  "project": "my_project",
  "dbName": "test_db",
  "sqlQuery": "SELECT * FROM users",
  "dbList": ["db1", "db2"],
  "tableList": ["t1", "t2"],
  "currentPage": 1,
  "pageSize": 50,
  "lastExecutedSql": "SELECT * FROM users LIMIT 10",
  "detached": false,
  "updatedAt": 1704067200000
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| tabId | string | Tab 唯一标识（UUID） |
| name | string | Tab 名称 |
| project | string | 当前选中的项目 |
| dbName | string | 当前选中的数据库 |
| sqlQuery | string | SQL 输入内容 |
| dbList | string[] | 数据库列表缓存 |
| tableList | string[] | 表列表缓存 |
| currentPage | number | 当前分页页码 |
| pageSize | number | 每页条数 |
| lastExecutedSql | string | 最后执行的 SQL |
| detached | boolean | 是否为分离窗口的 Tab |
| updatedAt | number | 最后更新时间戳 |

**恢复流程：**
1. 读取 `states/sqlSearch/index.dat` 获取用户关联的 tabId 列表
2. 根据 tabId 列表读取所有 `<tabId>.dat` 文件
3. 组装成完整的 SQL 查询页状态

**写入策略：**
- 只写入当前操作的 Tab 文件，不触碰其他 Tab
- index.dat 仅在 Tab 增删/切换激活时更新

#### 4.5 `states/sqlMetadata/` - SQL 元数据缓存

```
states/sqlMetadata/
├── index.dat           # 元数据索引（项目列表）
├── my_project.dat      # my_project 项目的元数据
└── another_project.dat # another_project 项目的元数据
```

**index.dat 结构：**
```json
{
  "schemaVersion": 1,
  "source": "states.dat",
  "migrationStatus": "completed",
  "projects": ["my_project", "another_project"],
  "updatedAt": 1704067200000
}
```

**项目元数据结构（如 my_project.dat）：**
```json
{
  "admin": {
    "databases": ["db1", "db2"],
    "dbTables": { "db1": ["t1", "t2"], "db2": ["t3"] },
    "tableStats": { "db1.t1": { "rowCount": 1000, "dataLength": 51200 } },
    "fields": { "db1.t1": [{ "caption": "id", "value": "id", "meta": "bigint", "score": 100 }] },
    "timestamp": 1704067200000,
    "version": "1.0"
  }
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| databases | string[] | 数据库列表 |
| dbTables | Record<string, string[]> | 数据库->表映射 |
| tableStats | Record<string, TableStats> | 表统计信息（行数、数据大小） |
| fields | Record<string, Field[]> | 表字段信息（用于 SQL 补全） |
| timestamp | number | 缓存时间戳 |
| version | string | 缓存版本号 |

**写入策略（由 scheduler 调度）：**
- TAB（标签页）：立即保存
- SNAPSHOT（页面快照/路由/SQL元数据）：防抖 3 秒
- SIDEBAR（侧边栏）：防抖 1 秒
- ROUTE（路由）：防抖 1 秒

**写入时机：**
- 标签页/页面状态/侧边栏改变时（按上述策略防抖）
- 窗口关闭前强制保存（forceSave）
- 退出登录前保存

**读取时机：** 登录成功后恢复状态
**清除时机：** **点击「清除缓存」按钮时物理删除整个 states/ 目录**

### 6. `credentials.dat` - 设备凭据（Rust 端管理）

```json
{
  "admin": {
    "deviceKey": "encrypted_key_xxx",
    "bindTime": 1704067200000,
    "machineId": "machine_id_xxx"
  }
}
```

以用户名为 key，存储设备绑定信息，用于自动登录。

**由 Rust 端管理**，前端通过 `src/services/machine.ts` 调用：
- `hasDeviceCredentials(username)` - 检查是否有凭据
- `bindDevice(...)` - 绑定设备
- `unbindDevice(...)` - 解绑设备

**兼容性：** 首次启动时会自动将旧文件 `device_credentials.dat` 重命名为 `credentials.dat`

**写入时机：** 设备绑定成功（Rust 端）
**清除时机：** 解绑设备（Rust 端）

## 应用启动流程

```

│                      应用启动                                │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                   显示启动页"启动中..."                      │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  解密 app.dat                                                │
│  - 获取 lastUser（最后登录用户）                             │

└─────────────────────────────────────────────────────────────┘

│  检查 tokens.dat 是否存在                                    │
└─────────────────────────────────────────────────────────────┘

                    ┌─────────┴─────────┐

            [有 token 文件]       [无 token 文件]
                    ↓                   ↓
    ┌───────────────────────┐   ┌───────────────┐
```

## 登录流程

```
用户输入账号密码
    ↓
调用登录接口
    ↓
登录成功，获取 token
    ↓
检查"保存登录状态"开关
    ↓
┌─ 勾选 ────────────────────────┐
│   加密写入 tokens.dat         │
│   下次启动自动登录            │
└───────────────────────────────┘
│
└─ 未勾选 ──────────────────────┐
    │   token 仅存内存          │
    │   关闭软件后失效          │
    │   支持多开不同账号        │
    └───────────────────────────┘
    ↓
更新 app.dat（lastUser、loginHistory）
    ↓
加载用户数据，进入主页
```

---

## 退出登录流程

```
退出登录
    ↓
保存当前用户状态到文件
  - states.dat[username]（标签页、路由等）
  - preferences.dat[username]（主题、窗口大小等）
    ↓
调用服务端登出接口
    ↓
删除 tokens.dat 文件
    ↓
更新 app.dat
  - defaultTheme = 当前用户主题（用于未登录时显示）
    ↓
清空内存状态（store）
    ↓
跳转登录页
```

**说明：**
- 主题会写入两个地方：
  - `preferences.dat[username]` - 该用户的个人偏好
  - `app.dat.defaultTheme` - 未登录时的默认主题

---

## 切换账号流程

```
登录页面选择其他用户名
    ↓
检查 credentials.dat[username] 是否有设备凭据
    ↓
┌─ 有凭据 → 显示“自动登录”按钮
│
└─ 无凭据 → 仅显示手动登录（密码/双因子）
```

**说明：**
- 能进入登录页说明没有有效 token（有 token 会自动登录或已被删除）
- 登录成功前不修改任何文件
- 只需检查目标用户是否有设备凭据来决定显示哪种登录方式

---

## 清除缓存流程（头像菜单「清除缓存」按钮）

```
点击「清除缓存」
    ↓
window.location.href = '/dashboard?clear=1'（整页重载）
    ↓
App 启动→ init flow（恢复 token / theme / userName）
    ↓
clear flow：
    ↓
【步骤2】清除内存 + 物理删除文件
  ├─ scheduler.dispose()           取消未完成的防抖保存
  ├─ sqlApplyStore.stop()          停止 SSE 订阅
  ├─ menuStore.clearMenus()        清 menuList/menuPermissions/views
  ├─ pageStateStore.clearAllPageStates()
  ├─ menuStore.delAllViews()       重置标签页
  ├─ ✅ removeStorageDir('states/')       物理删除整个 states 目录
  └─ ✅ removeStorageFile('profiles.dat') 物理删除 profiles.dat
    ↓
【步骤3】重拉数据 + 重建 SSE
  ├─ fetchUserMenus()              重新获取菜单
  ├─ fetchProfile()                重新获取用户信息/权限
  └─ sqlApplyStore.start()         重建全局 SSE 订阅
```

**清除范围总表：**

| 文件/目录 | 是否清除 | 说明 |
|-----|---------|------|
| `app.dat` | ❌ 保留 | 公共配置（登录历史/默认主题/更新信息） |
| `tokens.dat` | ❌ 保留 | 保持登录状态，清除后不需重新登录 |
| `profiles.dat` | ✅ 清除 | 用户信息/权限/菜单快照，重新拉取接口 |
| `states/` | ✅ 清除 | 整个目录删除（导航/页面快照/SQL元数据等全部重置） |
| `preferences.dat` | ❌ 保留 | 主题/快捷键/窗口尺寸等偏好不变 |
| `credentials.dat` | ❌ 保留 | 设备凭据由 Rust 端管理，不受前端清除影响 |

**设计要点：**
- 物理删除目录（`removeStorageDir`）而非仅清内存，避免下次启动从文件恢复到旧状态
- 必须先 `scheduler.dispose()` 才能删文件，否则防抖期间未调度的 builder 会在删除后重新写回老数据
- SSE 需在步骤2 `stop`、步骤3 `start`，保证连接使用新拉取的用户信息
- 使用 `Promise.allSettled` 避免单个接口失败中断整个流程

## 数据迁移（states.dat → states/ 分片）

首次启动新版本时，自动将旧的 `states.dat` 迁移到新的分片架构：

```
检测 states.dat 是否存在
    ↓
┌─ 存在 ────────────────────────────────────────────────────────┐
│   1. 读取 states.dat 内容                                      │
│   2. 拆分导航状态 → states/navigation.dat                     │
│   3. 拆分页面快照 → states/page-states.dat                    │
│   4. 拆分 SQL 查询 Tab → states/sqlSearch/<tabId>.dat         │
│   5. 拆分 SQL 元数据 → states/sqlMetadata/<项目>.dat          │
│   6. 写入 states/index.dat（标记迁移完成）                     │
│   ℹ️ states.dat 保留不删除（供本地测试/下次清理）               │
└───────────────────────────────────────────────────────────────┘
│
└─ 不存在 ──────────────────────────────────────────────────────┐
    │   跳过迁移，直接使用分片架构                                │
    └───────────────────────────────────────────────────────────┘
```

**迁移规则：**
- `visitedViews`、`cachedViews`、`activeRoute`、`sidebarCollapsed` → `navigation.dat`
- `pageStates`（排除 `sql/search`、`sql/detached-tabs`）→ `page-states.dat`
- `sql/search`、`sql/detached-tabs` 页面状态 → `sqlSearch/<tabId>.dat`（按 Tab 拆分，每个 Tab 一个文件）
- `sqlMetadata` → `sqlMetadata/<项目名>.dat`（按项目拆分）
